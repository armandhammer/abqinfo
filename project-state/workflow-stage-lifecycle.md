# Workflow stage regression lifecycle

The owner authorized this architecture for PR #194; the invocation is saved in `discovery/planning-publication-lifecycle-authorization-2026-09-26.json`. `workflow-stage-lifecycle.json` records the contiguous Git boundaries of each completed stage and the active stage, plus independently completed audits such as the original mission-scope correction. It grants no external-action, publication or merge authorization.

A completed stage retains every assertion about its original authorized population, mutations, provenance, archive receipts and governing evidence. `StageSnapshot` reads stage-owned mutable state at that stage's registered endpoint. Content invariants compare the original baseline to that endpoint, including content, layouts, assets, static files and visitor-visible configuration. They do not assert that subsequent work cannot exist.

Evidence files remain live and protected. Their normalized bytes must equal the registered immutable Git blobs; changing a snapshot endpoint cannot silently replace the sealed evidence hash. The lifecycle regression checks continuous stage boundaries, ancestry, required regression scripts and protected evidence, then executes the active stage's exact-delta guard. It runs through the normal project suite without an environment switch, assertion suppression or alternate suite.

For the next authorized stage, checkpoint the completed current stage, record its immutable endpoint, and append the next stage using that exact commit as its baseline. The new stage must declare a guard and its regression scripts, and those scripts must run in the ordinary suite. A gap, missing guard or multiple active stages fails validation. Preserve all existing boundaries and evidence hashes; add new evidence seals rather than replacing completed-stage evidence. An earlier publication regression can then use its endpoint through the same `StageSnapshot` API instead of requiring new exceptions in older tests.

The current Planning guard covers exactly the twelve archive-verified records and the six approved pages. It compares the complete inventory population, forbids changes outside the authorized records and fields, pins the authorized final row values, checks the original placement-assigned states and positive mission scope, preserves source/provenance fields, and requires unchanged R2 state. Approved page hashes use UTF-8 bytes with normalized line endings and retain a witness in the original publication commit. Source and rendered regressions retain the incomplete Impact Area family, Barelas duplicate suppression, separate official/archive links, section anchors and both approved cross-links. Rendered and preview checks inspect the delivered HTML and the descriptions. The derived retained-source queue adds exactly the twelve newly implemented sources as pending roots, preserves every prior audit result, and cannot claim that new descendant research was performed.
