# Autonomous background campaigns

Repository state is the workflow specification after `/new`, context compaction, account switching or interruption. Read AGENTS.md, CURRENT.md, checkpoint.json, active-campaign.json, the referenced campaign and profile. Conversation is disposable. Do not reset an unfinished campaign, repeat sealed review, or infer permission from saved prompts.

## Authority and scope

AGENTS.md controls mission scope, quality, full-family relationships, missing-minutes policy, protected gates, publication and external authorization. CURRENT and checkpoint identify current position; the inventory is authoritative for rows. The active pointer identifies exactly one campaign. Campaign selection locks allowed pending IDs and all baseline row digests. The source queue preserves gate reasons and bounded blockers. A profile defines behavior; it cannot invent authorization. The authorized current campaign may upload eligible originals <=150000000 bytes, perform exact public GET verification and integrate background-only work. The project ceiling is 13000000000 decimal bytes in r2-storage-policy.json. Never delete or overwrite for capacity. No content/ edits, publication or protected/human-family review.

## Launch and review

Use PowerShell 7 and existing deterministic tools. Verify branch/worktree, preserve unrelated files and backups. Recompute the queue if stale. Get a complete live R2 listing with Get-R2Inventory.ps1 to a new evidence path; compare saved/live key, size and ETag before launch. Start with `python -B scripts/project/BackgroundCampaign.py start --id <unique-id> --queue <current-queue> --live <fresh-listing>`. A new ID never replaces an unfinished campaign. `status`, `prepare`, `show`, `review --decisions <file>` and `apply` use the active pointer and family selection. Saved recommendations are evidence, never automatic approvals.

Review each complete family from saved full-source research. Inspect actual content and rendered static originals, verify source size/SHA-256, evaluate both scope gates and quality, check exact aliases and chronology. Use format-specific inspection for Word/slides/sheets/live services; do not treat application HTML as a PDF. Preserve originals unchanged. Apply explicit dispositions through existing inventory gate scripts and persist each family immediately. A genuine uncertain decision stays unresolved with a concrete reason; do not create false exclusions or automatic human gates to claim exhaustion. Track bounded deterministic blocker recovery separately. Do not touch protected canonical rows when an alias can be resolved independently.

## Archive and interruption recovery

Archive-family evidence is copied into the active campaign; closed historical campaign artifacts remain immutable. Run Invoke-BackgroundCampaignArchive.ps1. Before mutation, compare every baseline object by exact key/size/ETag, reject unknown objects, duplicate intents and casefold collisions, rehash source files, require positive scope and completed quality, check actual live storage and <=150 MB. Save absent-key upload intent atomically before PUT. Save uploaded-pending-verification immediately after return. Fetch the complete public object and verify exact size/SHA-256; save receipt before changing inventory. Refresh live R2, save accounting, apply placement metadata through the existing mission gate, then save archive-complete and checkpoint.

On any restart, reconcile the complete live listing first. An object with a saved intent is recovered by exact full public GET and identity verification, never another PUT. An unknown object, changed baseline ETag, size, key, collision or missing object stops mutations. Recover intent/receipt/inventory gaps idempotently. Failed public verification retains intent and remains unfinished. Run only one mutating worker; no simultaneous upload or inventory writers. Persist Git external-action intent and result in the campaign integration journal around push, PR creation/edit and merge. After interruption, inspect remote state before retrying.

## Closeout

Reconcile saved/live R2 and every intended upload. Recompute a record-level queue partition: gated, source/structural blockers, unresolved ungated; distinguish actionable from unresolved with specific evidence. Validate each changed row against baseline digests and exact authorized IDs; preserve unrelated and protected rows. Update CURRENT/checkpoint and active campaign, run Invoke-ProjectValidation.ps1, focused campaign regressions, git diff --check and prove content tree unchanged. Commit coherent checkpoints. Prepare a real Markdown PR body, validate Test-PullRequestDescription.ps1, integrate authorized background-only work, inspect remote SHAs and fast-forward local main and planning-snapshot without force or destructive reconciliation. Save final integration SHAs and validation artifacts. Mark complete only after all required work; otherwise state the exact remaining stage. Short future requests can refer to the profile or active pointer because execution and recovery instructions live here.
