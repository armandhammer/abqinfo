# Owner instruction: simplify routine, owner-supplied document publication

**Status:** owner-directed implementation specification, staged for integration after the active PR #219 post-merge session finishes. This file is not a substitute for registration in the durable governance registry and does not by itself release any R2, visitor-visible, or other standing gates.

## Problem and intended outcome

The October 12 Lead/Coal intake took multiple Codex sessions and produced task-specific Python validation machinery, 11 contract versions and a 41-file PR to publish two PDFs the owner had already placed in `research/staging/document-review/`. This is disproportionate to routine intake. Design and implement **one reusable, bounded, one-pass intake workflow** for straightforward owner-supplied documents, using the existing repository mechanisms rather than constructing a new mini-framework for each task.

The owner's placement of files in `document-review/` and identification of an existing site section are strong evidence of editorial intent and expected relevance, **not** conclusive proof of source authenticity, substantive quality, adoption/finality, or approval for every external action. Confirm the material instead of repeating exhaustive discovery research.

## Routine intake: expected sequence

1. **Scope/authority:** Inspect current remote state and worktree, stop if another task is editing the same checkout; freeze the exact named files, related existing entries/family and target page. Resolve the **complete** active registry into an immutable task-governance contract using the established resolver. Respect all active rules, settled decisions, freshness gates and validation. Do not select applicable historical rules manually or weaken fail-closed checks.
2. **Fast PDF validation:** Hash exact original bytes; check PDF integrity, readable/renderable pages, page count, encryption, gross truncation and missing/blank pages. Inspect cover/title/date, contents or executive summary, representative substantive pages and ending/appendices. For map-only/visual documents inspect the relevant visual material. Extract text where practical. Escalate to full-page inspection only for suspected corruption, poor scans, ambiguous substance, unusual version/finality, or a rule requiring it. Record exactly what was inspected. The purpose is a defensible quality assessment, not an automatic 100%-page screenshot campaign.
3. **Targeted editorial/provenance check:** Identify the document's actual subject, publisher, date, status and official or historical source; check the specified existing site section and targeted inventory/family for duplicates, replacement editions, prior dispositions and material overlap. Populate the required scope and quality assessment fields with concise real evidence. Do not turn a supplied two-PDF task into a general source-recovery campaign. Escalate genuine uncertainty and do not misrepresent drafts or proposals as adopted policy.
4. **Archive:** Only when currently authorized for the exact action, obey the standing R2 storage/object ceilings, ensure absent destination keys and no overwrites/deletions, upload unchanged originals, then retrieve each complete public object and compare SHA-256 and byte count. Preserve provenance and originals. If authorization is missing, prepare the exact bounded request/plan; do not infer it from mere folder placement.
5. **Page/PR:** Add only the approved entries in the existing heading using concise, useful descriptions, full R2 URLs and official or verified historical source links. An owner-requested, specifically bounded 1–3-document content PR is a legitimate exception to the normal large-batch preference; implement this explicit exception through governance supersession if necessary. Prepare a verified nonproduction preview and a clear human-readable PR showing exact visible differences. **Never merge a visitor-visible PR autonomously.**
6. **Record/close:** Use existing inventory, receipt, link-check, Hugo, governance and full validation tools. Preserve a small durable completion record, rather than redundant evidence copies or 10+ contract regenerations. Following the owner's manual merge, verify the production section and archive links, mark the task complete and reconcile `main` / `chatgpt/planning-snapshot` using current repository policy. Do not restart document review or build new tests during ordinary post-merge closeout.

Inspect the actual PR #219 changes, workflow-stage lifecycle, registry resolver, validation runner and relevant historical guards; do not guess.

One generic intake helper/checklist is acceptable **only if actually useful**; otherwise use existing commands and a short documented procedure. Do not add a new Python module, governance stage, validator or test registration for every document pair. Do not rewrite unrelated historical validators, alter old sealed evidence, or fabricate authority to make tests pass.

## Completion criteria

A new Codex session can process a named, ordinary owner-supplied PDF into a safely archived, owner-review-ready content PR **in one bounded task** (subject to pre-existing R2 authority). Subsequent post-merge reconciliation is a narrow verification task. No per-document custom test runner, repetitive full-document research or avoidable cascade of governance contract versions is necessary. Stop and report a specific blocking governance/system defect if the existing mandatory safeguards make this impossible; do not solve it by expanding the task indefinitely.
